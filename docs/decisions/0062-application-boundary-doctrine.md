---

**The runway asked what a public reference application may be, and what this repository may hold once runnable application code exists. Most of the answer was already law, and this record gathers it: what the public side is made of, what may never reach it, how the world beyond it is referred to, and what a release may claim. One part of the answer the sources do not settle. The last item of the exclusion list turns on what *the public Wing* denotes once the project could publish something a person might install and operate, and the sources hold text for two meanings and none that chooses between them. This record says so, sets the two readings side by side, and decides neither.**

## Decision question

**From the published sources alone: what may a public reference application be; how do the constructional test and the closed exclusion list bind application code, demonstrations, examples and release evidence; in what words is anything beyond the public reference build referred to; and does any part of the proposed release need a governing change or a different home — decided now, as fixed input to W9-D2 through W9-D7, without building anything and without selecting a reading to suit a preferred route?**

## How to read the rules

Every rule below carries one of four marks. **[carried]** — the cited accepted source states the rule, and this record applies it without change. **[extension]** — the cited law did not name the class of thing in question; this record applies it to that class by its own ceremony, as ADR-0046 decisions 2 and 12 permit a later record to extend and never to narrow. **[reading]** — the cited text admits more than one reading on the point and no source states the one this record proposes; the record shows its grounds and states what they establish and what they do not. A [reading] binds only if the human reviewer accepts it, and whether a reading that limits a rule's reach reads that rule down is for the human reviewer to judge in accepting or refusing it. **[open]** — the published sources do not decide the point, and this record does not decide it either. **No rule is derived from the proposed release, and nothing is described as existing unless a source is cited for it.**

## Decisions

### Part A — The door

1. **This record decides the boundary as far as the published sources decide it, and creates nothing inside it.** After its landing the repository contains exactly one new governed artefact: this record. No application, build, demonstration, example, capture, evidence record, schema, directory or dependency exists by reason of it.

2. **This record binds W9-D2 through W9-D7, and is consumed by them, not re-decided** (`W9-AR` §6.1; `W9-D1-BDB` item 27). A later record may extend its prohibitions through its own ceremony; none may narrow them by convenience. **A later deliverable may rely only on what this record establishes. Where a point is marked [open], or is a [reading] not accepted, no later deliverable may proceed as if it had been settled either way.**

### Part B — The terms

3. **The terms the boundary turns on, defined by what each thing is.** The distinction that matters is the role and provenance of an operation and of what it produces, never the place it runs.

| Term | What it is | Source |
| :---- | :---- | :---- |
| **The repository** | The tracked content of this project at any published commit, with its history | `W2-D3` rules 3 and 4 |
| **A project artefact** | Anything the project produces, holds or publishes: tracked files; commit, review and issue text; logs, findings, notes, captures and every text that work creates about the work; builds the project publishes, with their materials; retained evidence; and everything a project run produces | `W3-AR` §5 (*"the repo, tests, fixtures, logs, screenshots, or docs"*); ADR-0007 decision question and decisions 1 and 2 |
| **A project run** | Any operation of the code, of a reference build or of any part of either, made as project work: development, local debugging, tests, demonstrations, captures, the production of evidence, and review. **It is a project run wherever it runs and on whoever's machine**, and whether or not anything it produces is ever sent anywhere | ADR-0007 decision question and decision 1 (*"Every development artifact — local debugging included — uses synthetic fixture data only."*); `W3-AR` §5 (*"the synthetic-only discipline extends into the runnable era via the dev-artifact policy"*) |
| **The public reference application** | Tracked source for a runnable caller of the sealed engine and the runtime. None exists: the engine's own account is *"No UI, no CLI, no network, no model contact — one API, its tests, and nothing else."* | `engine/README.md`; `W9-AR` §3 and §4, where it is a proposal |
| **A reference build** | A runnable object made from a published commit and published by the project. It is a project artefact. **A copy of it carries the same provenance**: copying a build changes where its bytes are, not what they are or who made them | [extension] — the sources name it only as a proposal |
| **An installation** | A copy of a reference build operated **other than as project work**. Its bytes stay those of the build the project published. What is not a project artefact is what that operation holds and produces inside the local runtime of whoever operates it, and only while none of it is brought into a project artefact. **Location, ownership of the machine and the absence of any transmission do not make an operation an installation**: a project run on a machine its operator controls is still a project run | the distinction between a project artefact and *"that user's local runtime"* (`W3-AR` §5), with ADR-0007 decision 1; W1-D1 §1, zone Z1. **This record does not say that any operation of this kind is lawful, contemplated or prepared** (decisions 14 and 30) |
| **A local runtime** | The inside of the trust boundary of whoever operates a copy: their device, their key material, their unlocked session. A project run's local runtime is not thereby outside the project: what a project run produces is a project artefact | W1-D1 §1, zone Z1; ADR-0001; ADR-0007 decision 1 |
| **Release evidence** | A retained project artefact offered in support of a claim a release makes | `W9-AR` §3 and §5 question 6 |
| **A channel** | Any path by which bytes could travel from an installation to the project or to anything the project controls. **The term describes a class of path; it is not itself a prohibition.** Part H states which paths the standing law forbids and which human acts it governs by their content. Publication by the project runs the other way, from the project outward, and is not a channel in this sense | `W9-D1-BDB` item 10; in the terms of W1-D1 §0, a flow |

4. **Three terms the sources do not close.** `W9-AR` §8 lists *demonstration*, *example* and *walkthrough* and defines none of them. This record closes them no further than this: **each is a project artefact that shows or supplies material for the application at work**, and every rule here that binds a project artefact binds all three. Finer distinctions are not drawn from preference.

### Part C — The reach of the constructional test

5. **What ADR-0046 decision 4 says, and of what.** *"The test is constructional, not custodial. A W7 artefact, path, field, or process that could carry real-person content is unlawful regardless of whether it currently does."* Its subject is the artefact, path, field or process **of the public phase**: the record's own decision question begins *"What is public W7 permitted to be made of, what may it never contain"*. `W9-AR` §8 carries the law into W9 in the same terms — *"No public W9 record may contain"* — and for everything a W9 deliverable proposes: *"Every fixture, demonstration, example, walkthrough and evidence record a W9 deliverable proposes is authored from nothing."* **[carried]**

6. **The test binds the whole public side, by construction, and project work wherever it runs.** Every project artefact is synthetic by construction, never by scrubbing (W2-D4 rule 1; ADR-0007 decision 1; ADR-0046 decision 3). A tracked data file, a field of a tracked data shape, a repository path or a project process that would come to hold content from an installation or from any real person **is unlawful on the day it is defined, not on the day it is filled**. Emptiness is not conformance. **Project development, tests, demonstrations, captures and the production of evidence keep every obligation that binds them wherever they run**: on a machine the person doing the work controls, offline, and whether or not anything is ever sent. ADR-0007 decision 1 binds every development artefact, local debugging included, and rejects any own-data quick-test exception; neither the place of a run nor what it is called discharges it. **[carried]**

7. **A reference build is on the public side, and so is every copy of it.** A build the project publishes carries code and synthetic material only. Its bundled content and its default values are authored from nothing or are empty; nothing in it derives from any real person's content, however transformed. Copying it changes where its bytes are and nothing they are: the rule binds the bytes of every copy. **[extension]**

8. **What an installation holds is not a project artefact; what it brings to the project is.** *"a real user's real data exists only in that user's local runtime, never in any project artifact"* (`W3-AR` §5). The constitution's object is a person's own information held inside that person's trust boundary (W0 §1 and Law 11; ADR-0001; W1-D1 §0 rule 3). **[carried]** Three things this does not reach, each kept on the public side: every project run, wherever it runs (decision 6); the bytes of the build itself, in every copy (decision 7); and anything brought from a local runtime into a project artefact, which is then a project artefact under every rule of this record and lawful only if it could lawfully be there (decisions 16 and 32). **[carried]**, applied to the terms of decision 3, with decision 7's extension for copies.

9. **Whether decision 4 reaches a field defined in tracked code by reason of what that field could hold in an installation: a proposed reading.** **[reading]** The tracked code is a project artefact, and its field definitions are part of it. In a project run the field holds synthetic material only, by ADR-0007 decision 1 and the capture rule (decisions 6 and 18). In an installation, what the field holds is in a local runtime that is not a project artefact (decision 8). This record proposes that **decision 4 binds every project artefact, path and process that could come to carry real-person content, including any path by which an operation's content could reach the project (decision 10), and does not make a code-defined field unlawful by reason of what an operator could place in it inside a local runtime that is not a project artefact.** Its grounds, and what each establishes:
   - **The text.** Decision 4's subject is *"A W7 artefact, path, field, or process"*, and its record's decision question begins *"What is public W7 permitted to be made of"*. Its example is *"A field that would accept a real transcript is a defect on the day it is defined, not on the day it is filled."* The example does not say where the field stands. **Reading it as a field of a project artefact is this record's interpretation, not the text's words.**
   - **The older distinction, never amended.** `W3-AR` §5 places a real user's real data in that user's local runtime and never in any project artefact. ADR-0046 states of itself: *"No law is amended."* That distinction stands. It does not itself say how far decision 4 reaches.
   - **The history: compatibility, not a ruling.** The sealed engine was published in July 2026 and the runtime in August 2026, and both stood in the tree when ADR-0046 landed. The engine's import boundary takes *"bytes plus user-supplied provenance"* (ADR-0009 decision 1). ADR-0046 says that after its landing *"the repository contains exactly one new governed artefact: this record"*, and its statement of what it does not touch names neither. **This history is compatible with the proposed reading. It does not establish it**: no accepted record rules on the reach of decision 4 to a code-defined field, and the corpus's silence on the point is not a ruling on it.
   - **What the reading does not do.** It does not make anything a person could install lawful to hold here; that is the separate question of decision 14. It relieves no project run of anything (decision 6).

   **If the reading is not accepted, this record does not decide the reach of decision 4 to such a field**, and no later deliverable may rely on it either way (decision 2).

10. **The test follows an application's own paths wherever they lead to the public side.** A path or process **defined in application code** by which content an installation holds, or any record or diagnostic of its operation or use, could come to rest in a project artefact or in anything the project controls ends in a project process that could carry real-person content, in the sense decision 4 fixes and the law carries forward. **It is unlawful by construction: the existence of the path is the defect, not its use**, whether it would run by itself or on a person's action within the application. **This rule reaches paths defined in application code only.** It does not reach a person's own deliberate act of sharing, which the standing law governs by content (decision 32), and it withdraws nothing ADR-0007 decision 7 provides. Part H applies it. **[extension]**

11. **The two readings the brief names, tested.** On the first, the law binds what the repository, and any channel the project controls, may hold. On the second, the constructional test reaches an application's own fields wherever they run. **Each holds in part and neither holds whole.** The first states correctly what the test binds: the whole public side and every project run (decisions 6, 7 and 10). The second is right that the test does not stop at the repository's edge when an application's own path leads back to the public side (decision 10). Where the second would make a code-defined field unlawful by capability alone, this record proposes that it does not hold (decision 9), on grounds that are compatible with that proposal and do not establish it. **Neither reading settles the last exclusion family** (decision 14).

### Part D — The exclusion list, read against an application

12. **Ten families, each read against what an application release would add to the repository or publish from it.** Nothing here reads a family down, shortens it or softens it (ADR-0046 decision 12). **This record adds no family to decision 11's list and does not edit that list**; each row applies an existing family to classes of thing the list has not yet met. **[extension]**

| Family (ADR-0046 decision 11) | What it forbids in code, configuration and defaults, packaging, logs and diagnostics, demonstrations, examples and walkthroughs, documentation, release evidence and commentary |
| :---- | :---- |
| Real-person data of any kind | Any real person's data in any of them: none as a default, a sample, a test input, a screenshot, an illustration or an evidence record |
| Any identified person's room, health, movement, food, device, contemplative or journal material | The same, for each room's material; persona tokens stay in the artificial form W2-D4 rule 3 fixes, and no human-plausible name appears |
| Real wearable or device data | Any sample, export, trace or identifier from a real device, in any class; `W9-AR` §9 also bars device-originated data from the application itself |
| Private relationship or lived-interaction material | Any recorded lived exchange used as a demonstration, example, walkthrough or evidence, in any form or derivation |
| Private model transcripts | Any model transcript in any class. No generated text can exist under the standing model boundary (`W9-AR` §9) |
| Credentials, tokens, keys, secrets or private configuration | Any secret or signing key in code, defaults, packaging or evidence; any configuration taken from a real machine or a real person's setup. Integrity hashes and public record identifiers are not secrets |
| Machine-identifying detail beyond OS class | Hostnames, usernames, device names, serial numbers, local folder paths and capture metadata in logs, diagnostics, captures, documentation and evidence (ADR-0007 decision 4); environment evidence is stated at class level only |
| A model binary | Any model weight or binary in the repository or in a build |
| A real-person evaluation channel | Any intake, endpoint, form or process by which a person's use is observed, measured or collected, in code or in the evidence method (ADR-0034 decision 10) |
| Private adoption implementation detail | Any detail of anything the fixed invariant refers elsewhere, in any class (ADR-0046 decision 16; ADR-0052 §5.4) |

13. **The eleventh family: what the sources fix.** The family is *"anything that would turn the public Wing into a live personal instrument"*.
    - **What the sources say the public Wing is, and where they stop.** *"The public repository proves the pattern. Everything lived is elsewhere."* (`W7-AR` §4). A build the project publishes is a project artefact and part of the public side, in every copy (decision 7). What an installation holds in its local runtime is not (decision 8). **[carried]**, with decision 7's extension for copies. **No source states whether *the public Wing* also denotes a published build as it would operate in an installation** (decision 14).
    - **The family is a consequence clause.** *"It is a consequence clause: its subject is what an artefact would do if run or adopted, not what any artefact contains. Deciding it requires reasoning about effect."* It is review-only: no pattern decides it, and it is the item *"that most needs a person to have looked"* (ADR-0052 §5.4). **[carried]**
    - **What it forbids on any reading.** A project artefact that holds or reaches a real person's data, configuration, account or device; any path Part H forbids; and any artefact shaped to one person's life. Each is already barred by another family or by Part H, and the eleventh family bars it again as a consequence. **[extension]**
    - **The one published judgement of effect.** `W7-D4-SHR` found no violation because *"Nothing it contains can be pointed at a person: there is no runtime path, no intake, no store, no model and no channel"*. Those were sufficient grounds for that landing. The record does not say they are necessary ones. **[carried]**

14. **The eleventh family against an installable build: not decidable from the published sources.** **[open]**
    - **The class assessed.** A reference build the project would publish, which a person could install and operate, and which, operated, would have a runtime path, would take in what its operator gives it and would keep it in a store, inside that operator's local runtime. These are the properties the one published judgement of effect found absent (decision 13). No such build exists.
    - **The unresolved question.** Whether a build of that class, held in and published from this repository, is something that *"would turn the public Wing into a live personal instrument"*. ADR-0052 reads the family's subject as *"what an artefact would do if run or adopted"*. What the sources leave open is what the clause denotes for this class: **whether *the public Wing* is the Wing as the public side holds and publishes it, so that what a copy would do in a local runtime that is not a project artefact is not the public Wing's doing; or whether it is the published artefact wherever it operates, so that a build which, installed, would be its operator's own instrument is the public Wing turned into one.** Neither ADR-0046 nor ADR-0052 defines *the public Wing* or *a live personal instrument*, and no accepted record applies the clause to an artefact with these properties.
    - **Why the sources do not decide it.** Each meaning has text behind it, and no text chooses between them.
      - **For the first meaning:** `W7-AR` §4 distinguishes the public repository from everything lived; `W3-AR` §5 places a real user's real data in that user's local runtime and never in any project artefact; the sealed engine already holds a store and an import boundary; the accepted corpus designs the Wing for a person's own information throughout (W0 §1 and §3; ADR-0001; ADR-0011; ADR-0012); and the fixed invariant refers every real-person adoption elsewhere, so that, on this meaning, what a copy would do if adopted is not the public Wing's doing.
      - **For the second meaning:** the family's subject includes what an artefact would do *"if run or adopted"*, which for an installable build is what it would do once installed; the one published judgement cleared a landing because it had *"no runtime path, no intake, no store"*, and this class has all three; ADR-0046 decision 17 holds that no W7 artefact may depend on the external side the fixed invariant refers to, wait for it, *"prepare for it, or be shaped by an assumption about it"*; and the list is growable only, and *"A W7 landing that would be easier if an item were absent is the exact circumstance the list exists for"* (ADR-0046 decision 12).
    - **What does not settle it.** ADR-0052's review-only classification settles who must reason about effect, and that no machine can; it does not by itself show that the sources cannot answer the question. That no accepted record has met the case is not offered as proof that the sources are silent: **the finding rests on the two meanings above, each with text behind it and neither chosen by any text.**

    **This record does not choose between them, and no mechanical result can.** `W9-D1-BDB` items 14, 24 and 41 require a point the sources leave open to be reported as open.

15. **What a decision of decision 14 would need, what it would settle, and what it would not.**
    - **What it needs.** The human reviewer's own governing judgement of what the clause denotes for the class of decision 14, recorded by an accepted record under full ceremony, with the standing human-review duties. This record prescribes no answer.
    - **If the clause is judged to bar that class,** the list cannot be narrowed to admit it (ADR-0046 decision 12). An installable build is then not within this repository on any reading. **It needs a different home**, and this record says that in those words and no more.
    - **If the clause is judged not to bar that class,** every element of the proposed release that needs a build is within the standing law only under the rules of Parts C to H, each of which then binds without exception.
    - **What no answer does.** A judgement of what the clause denotes is not a judgement of any build's effect. The family stays a consequence clause, applied to what each exact candidate would do: **every landing that would hold or publish a build owes its own judgement of effect under the eleventh family, over its exact bytes, in a fresh P4b act** (ADR-0052). No generic act, given once, clears the family for builds not yet made, and none replaces that act.
    - **Until a judgement is effective,** no later W9 deliverable may rely on a reference build being lawful to hold here, and none may rely on its being unlawful.

### Part E — Demonstrations, examples and captures

16. **Origins.** Every input to a demonstration, example, walkthrough, default content or evidence artefact traces to exactly one of the three lawful origins: authored synthetic material, repository fixtures and fixture-derived material, or governed public records *"cited rather than reproduced"* (ADR-0046 decision 7). **A fourth origin is unlawful** (its decision 8). **Content produced by or taken from an installation, or contributed from any person's use, is a fourth origin however it is transformed.** A project run over synthetic material is lawful project work (decision 6): what it is given traces to the three origins, and what it outputs is a capture and no origin at all (decision 17). **[extension]** — decision 7's subject was the artefacts of public W7; `W9-AR` §8 carries the law unweakened.

17. **A capture is terminal, and nothing routes it back in.** A screenshot, recording, log sample or output saved from a project run is evidence of what the build did. It is none of the three origins, and it never becomes an input to anything else — not a fixture, a demonstration, an example, default content, a doctrine record, a summary or another capture — under any origin and by any later relabelling: ADR-0046 decision 9 closes the path to origin (a) *"by later re-labelling"*, and the same holds for origin (c). Three cases are kept apart, and none of them is a recirculation exception:
    - **Independent authorship.** New material may be authored under origin (a) only if it is written from nothing: not reconstructed, transcribed, paraphrased or otherwise derived from the capture. **Calling a derivation authored from nothing changes no origin.**
    - **Citation.** A governed record that holds a capture may be cited under origin (c) for what it is and for its lawful governance finding. **The citation may not carry the captured payload back in as input**, under origin (a) or origin (c). A containing record's accepted status does not turn its terminal payload into input material.
    - **Retention and review.** A capture may be retained, and reviewed, within the governed purpose for which it was made.

    **[extension]** — ADR-0046 decision 9 states the rule for captured generated and specimen text; its decisions 7 and 8 close the origins for every artefact.

18. **Capture is publication, checked at capture time.** Every act that moves output of a running build into a project artefact is a new publication event, checked by the act that captures it; upstream cleanliness never transfers; and *"A capture that cannot be checked at capture time may not be made."* (ADR-0046 decision 5; ADR-0007 decision 2). **[carried]** A capture is made only of a project run operating on synthetic material, and carries no machine-identifying detail; output of an installation is never captured into a project artefact. **[extension]**, applying decisions 6, 8 and 16 to captures.

19. **Commentary carries no content.** Commit, review, issue, board, registry, release-note and packet text carries identifiers, categories, counts and behaviours only — no content string from any store, **synthetic included** (ADR-0046 decision 6; ADR-0007 decision 6). **[carried]**

20. **Declarability is the admission condition.** A demonstration, example or evidence artefact that holds content must be able to declare, as data: that it is synthetic, as a literal machine-checkable assertion; the origin of each input, from the closed three; the citation or identifier locating that input; whether it holds a capture, and that the capture is terminal; and the exclusion-list and scan status of its own bytes. **An artefact that cannot declare these cannot land.** The marker block of W2-D4 §4 is the precedent for the shape. **[extension]** — ADR-0046 decisions 19 to 22 state the condition for the artefacts of public W7. **A declaration is not its own proof.** Its presence and shape, its non-empty identifiers, its origin values against the closed set and its terminal-capture flag are checkable by machine once an instrument exists. Whether the declared origin is true, whether the material was made from nothing, and whether anything was derived from a capture are not, because lawful and barred material can be *"byte-identical in form"* (ADR-0052 §5.3 and §5.4). Part K keeps the two apart (B5). **[carried]**

21. **The shape is not decided here.** File names, field names, nesting and any schema belong to the record that first creates such an artefact, inside decision 20. **This record authors no artefact and defines no file, field or schema.**

### Part F — Release evidence

22. **The laws that bind retained release evidence.** It is synthetic-only by construction, with no real user content, no real room state and no real grant (ADR-0034 decisions 10 and 12). It is scanned exactly as documents are, with no exemption for machine production (ADR-0034 decision 34; ADR-0046 decision 13). It is never presented as a safety, health or `certif-` claim, in any summary or derived artefact (ADR-0034 decision 37; W0 Non-Goal 7). It carries no machine-identifying detail beyond OS class (ADR-0007 decision 4). It is produced by project runs only (decision 6), and it is declarable (decision 20). **[carried]**

23. **No evaluation channel to a person.** *"no evaluation channel to a person exists or may be created"* (ADR-0034 decision 10). Release evidence may not be produced by observing, measuring or collecting any person's use of an installation, and an evaluation involving a real person's content needs an authority this repository does not hold and does not anticipate (ADR-0034 decision 12). **[carried]**

24. **What follows for form, and what does not.** Evidence must be producible without any person's content and without any channel to a person. For evidence of comprehension the standing law admits synthetic-persona testing and nothing that measures a person (ADR-0012, testing requirements; ADR-0034 decision 10). **Whether any other lawful form exists is W9-D6's to settle inside this boundary.** This record settles no form, accepts no criterion and ranks none. **[carried]**

25. **A claim follows its evidence.** A release may claim only what retained evidence in a lawful form supports (`W9-AR` §3). A claim that could be supported only by evidence this Part bars cannot be made on the public side. **[carried]**

### Part G — The invariant, and where the public side ends

26. **ADR-0046 decisions 14 to 17 are carried unchanged.** The fixed clause, the sentence-position grammar that alone may vary, the non-naming law, and the rule that stating the clause creates nothing, opens nothing and establishes no dependency. In public records the external side is named in exactly one way:

> **Any real-person adoption is a separate governed authority outside this repository.**

27. **Every project artefact refers to anything beyond the public reference build in that form and in no other.** Application text, in-application strings, documentation, release notes and evidence are project artefacts, and are bound exactly as records are. The exact-form proof of the clause continues to hold over every tracked text it reads, at the reach B1 states. The non-naming law remains review-only in full, and no green result is evidence for it in any degree (ADR-0046 decisions 29 and 30). **[carried]**

28. **Where the public side ends.**
    - **It ends at the project artefact.** The repository, every build the project publishes and every copy of one, every project run wherever it runs, and every demonstration, example, capture, evidence record and claim is on the public side and is synthetic by construction. What an installation holds in its local runtime is not on the public side (decision 8). **[carried]**, with decision 7's extension for copies.
    - **The design is public; no one's use is.** The accepted corpus holds the Wing's design for a person who holds their own information: its laws, rooms, edges, grants and rights (W0; W1-D1; W1-D2; ADR-0001). ADR-0046 amended none of it. No public record holds, describes or depends on any real person's use. **[carried]**
    - **The invariant is categorical.** It says *any*. This repository's records are therefore never the authority for a real person's adoption: no release contract accepted here extends to it, and no project artefact offers it, schedules it, supports it, describes it, prepares it or depends on it (ADR-0046 decisions 16 and 17; `W9-AR` §11). **[carried]**
    - **What a public reference application may be, hold and claim.** It may **be** a reference build of the governed pattern, if decision 14 is ever answered so that one may be held here, and then only as each build's own judgement of effect allows (decision 15). It may **hold** code and synthetic material only. It may **claim** only what retained synthetic evidence supports, and nothing about any person's use. **[carried]** and **[extension]**, on decisions 7, 15, 22 to 25 and the invariant.

### Part H — Channels

31. **The standing law defines no flow of governed data to the project, and consent cannot create one.** *"The map is a whitelist. A flow that does not appear in §5 does not exist."* (W1-D1 §0). The whitelist holds no edge from any home or zone to the project. *"Consent authorises edges; it cannot create them."* (W1-D2 §0). A new edge needs a decision record with a constitutional check before any consent question can be asked. **[carried]** This states what the law defines. **It is not an observation that no path exists in any installation**: this record has no implementation to inspect, and it attests to nothing about one.

32. **Four domains, kept apart.** The term *channel* (decision 3) describes a class of path. The standing law treats four domains differently:
    - **(a) A path an application itself would perform toward the project** or anything the project controls. For governed data the whitelist defines none (decision 31). Automatic transmission of anything is barred: telemetry silence, *"proven by observation, never by documentation trust"* (ADR-0006 decision 2); for crash and debug artefacts, *"Never automatic transmission."* (ADR-0007 decision 7); analytics of any kind, a forbidden class (ADR-0004 decision 3); updates user-initiated only, with no background process (ADR-0006 decisions 3 and 4). **[carried]** A path defined in application code by which content an installation holds, or a record or diagnostic of its operation or use, could reach the project is unlawful at definition, whether it would run by itself or on a person's action within the application (decision 10). **[extension]**
    - **(b) A person's own deliberate act of sharing.** ADR-0007 keeps it, bounded by content: crash and debug artefacts are local files, plaintext-free with respect to governed content, inspected before any sharing and shared only by deliberate human action (decision 7); paste is publication, re-checked at paste time by the person pasting (decision 2); commit, review and issue text carries no content string from any store, synthetic included (decision 6); and every development artefact is synthetic only (decision 1). **What such an act brings into a project artefact becomes a project artefact, bound by every rule of this record.** The act is no permission to submit any real person's content, a capture's payload or any store's strings. Anything real is reproduced with synthetic fixtures before it is discussed, and *"that discipline gets designed with support processes in a later era, not improvised"* (ADR-0007, consequences). **This record keeps that rule as it stands, narrows it in nothing, and designs no support process.** **[carried]**
    - **(c) Publication by the project.** The project publishing its own artefacts moves bytes outward, not from an installation. It is not a channel in the sense of decision 3, and it is bound by every rule for project artefacts. **[carried]**, applying the term's own words.
    - **(d) Evaluation intake.** *"no evaluation channel to a person exists or may be created"* (ADR-0034 decision 10). **[carried]**

    The classes the brief names, each against those domains:

| Class | What the standing law holds |
| :---- | :---- |
| Telemetry and analytics | Barred. *"Verifiably telemetry-silent — proven by observation, never by documentation trust."* (ADR-0006 decision 2); analytics of any kind is a forbidden artefact class (ADR-0004 decision 3); governance metadata admits no analytics and no behavioural profiling (W1-D1 §2) |
| Crash and diagnostic reports | Never automatic (domain (a); ADR-0007 decision 7; ADR-0004 decisions 2 and 3). Local files only, plaintext-free with respect to governed content, shared, if at all, by a deliberate human act under domain (b); what is shared becomes a project artefact |
| Update checks | Updates are user-initiated only, with no auto-update machinery and no background process (ADR-0006 decisions 3 and 4). Decision 10 bars any update path by which content an installation holds, or a record of its operation or use, would reach the project |
| Support and issue text | Domain (b): paste is publication, re-checked at paste time; no content string from any store, synthetic included (ADR-0007 decisions 2 and 6). Anything real is reproduced with synthetic fixtures before it is discussed (ADR-0007, consequences) |
| Contributed examples | Authored from nothing, or not admitted. Derivation from any real person's content, *"including anonymised, aggregated, paraphrased, or "inspired by""*, is prohibited (W2-D4 rule 1; decision 16). A contribution is a deliberate act under domain (b), and what it brings is a project artefact |
| Submitted evidence | None is taken from any person's use (decision 23; domain (d)) |

33. **What this Part states, and what it does not.** A path the law forbids at definition is unlawful whether or not anything ever travels on it (decision 10). **This record states law: what may not be defined, what is barred, and what is governed by its content.** It designs, selects and authorises no mechanism, no support process and no transmission of any kind, and **it makes no statement that any path exists, or does not exist, in any installation.**
